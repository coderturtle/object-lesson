# Decisions: Object Lesson

## ADR Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-08-17 | Initial scaffold as factory-output | Agent-native workshop teaching object-oriented programming fundamentals in Java to first-year college students, via harness-driven exercises with a deterministic javac/JUnit gate. |
| 2026-08-17 | Naming pass complete: **Object Lesson** (`java-oop-workshop` → `object-lesson`) | Chosen by coderturtle from candidates; repo, local dir, and mind-palace mirror renamed same day. |
| 2026-08-17 | Audience framed as subject-beginner, harness-fluent — the mirror image of `borrow-native`'s audience | This workshop's learners are genuinely new to OOP *and* Java, but assumed to already drive a coding agent daily; kept explicit and unhedged rather than softened, per the settled brief. |
| 2026-08-17 | Language/subject: Java, taught via the official Java Tutorials, "Objects First with Java"/BlueJ, and Exercism's Java track as canonical-curriculum anchors | All three are real, current, and specific (chapter/lesson/concept structure confirmed directly, not assumed) — see `docs/workshop-design.md`'s "Canonical-curriculum anchor" section. |
| 2026-08-17 | Deterministic gate = `javac` clean + JUnit green + Checkstyle clean (Google/Sun rule sets) | Mirrors `borrow-native`'s `cargo test`/`cargo clippy` pairing, with an explicit caveat: Checkstyle is closer to pure style/convention than `clippy`'s correctness-adjacent lints, so it strengthens the deterministic tier without claiming to catch design judgment (encapsulation reality, composition-vs-inheritance calls) — those stay in Coachgremlin's conceptual tier by design. |
| 2026-08-17 | Module-arc anchor: 8-module core arc (Classes & Objects → Constructors → Encapsulation → Inheritance → Polymorphism → Abstraction → Composition vs. Inheritance → Exception Handling) + capstone, with Generics/Collections folded into Abstraction as an optional graded extension | Sequenced by hard prerequisite, not anchor position — encapsulation is placed before inheritance deliberately (so `protected` has meaning and cosmetic getters/setters are caught early); exception handling placed last, corroborated independently by both Objects First (Ch14, after inheritance/abstraction) and Oracle (a separate "Essential Classes" trail, not the OOP-concepts trail). Full reasoning: `docs/workshop-design.md`'s "Why this order." |
