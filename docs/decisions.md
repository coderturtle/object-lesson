# Decisions: Object Lesson

## ADR Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-08-17 | Initial scaffold as factory-output | Agent-native workshop teaching object-oriented programming fundamentals in Java to first-year college students, via harness-driven exercises with a deterministic javac/JUnit gate. |
| 2026-08-17 | Naming pass complete: **Object Lesson** (`java-oop-workshop` → `object-lesson`) | Chosen by coderturtle from candidates; repo, local dir, and mind-palace mirror renamed same day. |
| 2026-08-17 | Audience framed as subject-beginner, harness-fluent — the mirror image of `borrow-native`'s audience | This workshop's learners are genuinely new to OOP *and* Java, but assumed to already drive a coding agent daily; kept explicit and unhedged rather than softened, per the settled brief. |
| 2026-08-17 | Language/subject: Java, taught via the official Java Tutorials, "Objects First with Java"/BlueJ, and Exercism's Java track as canonical-curriculum anchors | All three are real, current, and specific (chapter/lesson/concept structure confirmed directly, not assumed) — see `docs/workshop-design.md`'s "Canonical-curriculum anchor" section. |
| 2026-08-17 | Deterministic gate = `javac` clean + JUnit green + Checkstyle clean (Google/Sun rule sets) | Mirrors `borrow-native`'s `cargo test`/`cargo clippy` pairing, with an explicit caveat: Checkstyle is closer to pure style/convention than `clippy`'s correctness-adjacent lints, so it strengthens the deterministic tier without claiming to catch design judgment (encapsulation reality, composition-vs-inheritance calls) — those stay in Coachgremlin's conceptual tier by design. |
| 2026-08-17 | Module-arc anchor: 8-module core arc (Classes & Objects → Constructors → Encapsulation → Inheritance → Polymorphism → Abstraction → Composition vs. Inheritance → Exception Handling) + capstone, with Generics/Collections folded into Abstraction as an optional graded extension | Sequenced by hard prerequisite, not anchor position — encapsulation is placed before inheritance deliberately (so `protected` has meaning and cosmetic getters/setters are caught early); exception handling placed last, corroborated independently by both Objects First (Ch14, after inheritance/abstraction) and Oracle (a separate "Essential Classes" trail, not the OOP-concepts trail). Full reasoning: `docs/workshop-design.md`'s "Why this order." |
| 2026-08-17 | Relabeled Module 03 ← 02 and Module 06 ← 05 from "hard prerequisite" to editorial ordering; corrected their real hard prerequisites to 01 and 04 respectively | Workshop Review Panel's Instructional Designer persona found both "hard" claims didn't survive scrutiny (03←02 is a thematic echo, nothing structurally blocks encapsulation on a default-constructed object; 06←05 is contradicted by this workshop's own Oracle citation, which teaches Interfaces before Polymorphism). Rather than force a justification that doesn't hold, relabeled both as this workshop's editorial sequencing preference and corrected the table's actual structural prerequisite (03→01: needs fields to encapsulate; 06→04: needs overriding, introduced in Inheritance, not Polymorphism). Full reasoning: `docs/workshop-design.md`'s "Prerequisite reassessment." |
| 2026-08-17 | Module 09 capstone requirement made concrete: seeded design flaw must require 3+ concepts (encapsulation, inheritance/polymorphism, composition) jointly, not fixable one at a time | Workshop Review Panel's Instructional Designer persona found the capstone row asserted, not designed (arc table cross-references all "—", fixture fully deferred) — real risk of a flaw that only exercises 1-2 concepts. Named the concrete bar now so a future content-author (Coachgremlin) can't under-scope it; the fixture itself is still not built in this pass. Full spec: `docs/workshop-design.md`'s "Capstone requirement (Module 09)." |
| 2026-08-17 | Generics & Collections split: baseline `List`/`Map` usage is required-but-light inside Module 06's core gate; writing your own generic types stays optional | Workshop Review Panel's Instructional Designer persona found "optional" unrealistic — Modules 07-09 will plausibly need `List`/`Map` regardless. Rather than leave the whole extension optional (and have later modules quietly depend on it anyway) or promote all of generics to required (more than this arc needs), split the topic: collection usage required-but-light, generic type authorship still optional. Full reasoning: `docs/workshop-design.md`'s revised "Scoping decision." |
| 2026-08-17 | Added a design-level sandboxed/isolated-execution commitment for the deterministic gate (`javac`/JUnit/Checkstyle never run on the learner's or maintainer's bare host); Module 01's fixture-build step must stand up the actual runner before any exercise ships | Workshop Review Panel's Security-Conscious Reviewer persona flagged the missing commitment as a real gap given this audience is genuinely new to programming, not just new to a language (unlike `borrow-native`). This is a commitment about where checks run, not a built sandbox — no container/CI implementation exists yet. Full text: `docs/workshop-design.md`'s "Execution environment" paragraph under "The teaching method." |
| 2026-08-17 | Fixed a scaffold-template bug for this repo: `check-mirror-drift.sh` and `setup-hooks.sh` were copied into the private sibling (`object-lesson-private/scripts/`) by `scaffold-project.sh`'s `PUBLIC_CAPABLE` path, but that same script's own git-init step only ever looks for and runs `scripts/setup-hooks.sh` inside `$REPO_DIR` (the public repo — the only one that is actually a git repository; the private sibling deliberately isn't one, confirmed via `git rev-parse --is-inside-work-tree` failing there). Net effect: the pre-push hook silently never installs for any public-capable scaffold, not just this one. Copied both scripts into `object-lesson/scripts/` (public) instead and ran `setup-hooks.sh` there for real | Deliberate deviation from what the current scaffold template produces, not a silent one — chosen because the scaffold script's own later use-site (the git-init block) is direct evidence of intent, not a guess. Known residual limitation, not fixed here: `check-mirror-drift.sh`'s `MIRROR` path is `$ROOT/mind-palace/...` relative to wherever it runs; run from the public repo it can't see the private sibling's `mind-palace/`, so it will report "mirror missing" until the script itself is taught about the split. Harmless because the hook is warn-only (push still proceeds), but the drift signal itself is not yet reliable for public-capable repos — worth fixing upstream in the factory's internal `scaffold-project.sh`, out of scope for this session. See `docs/next-actions.md`. |
