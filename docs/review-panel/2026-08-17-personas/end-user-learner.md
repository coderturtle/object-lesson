# Critique — End-User / Target Learner lens

**1. Right now, there's no document written for me — only one sentence pretending to be.** I'm the first-year student deciding whether to start this. The only artifact that isn't explicitly an internal design doc is the README, and its entire pitch is: *"Agent-native workshop teaching object-oriented programming fundamentals in Java to first-year college students, via harness-driven exercises with a deterministic javac/JUnit gate."* I don't know what "harness-driven" or "a deterministic javac/JUnit gate" means, and the doc never tells me — it's the exact jargon-leak the brief asked to check for, and it leaked into the one sentence I'd actually read. Everything else in the repo (`workshop-design.md`) says up front it's an internal design pass, which is fair, but that means the learner-facing surface is currently just this one under-explained tagline plus a scaffold stub ("Add project-specific commands here"). I'd bounce before module 1 exists.

**2. The design doc is honest with itself about my subject-beginner status, and I appreciate that — but it doesn't yet prove that honesty survives contact with actual module text.** The audience section correctly separates "new to Java" from "new to OOP itself," which matches me exactly, and I'd trust a workshop that states this plainly. But the reasoning that will presumably become my module intros already leans on vocabulary I won't have yet — e.g. Module 04's justification, *"`protected` has no meaning before encapsulation exists,"* uses `protected` to explain why I'm learning about it later, which is circular if it reaches me before I've met the concept. Since "any module's actual exercise content" is explicitly out of scope for this pass, I can't yet tell whether it will talk down to me, over-assume design fluency, or land right — that verdict is simply not answerable from what exists today.

**3. Unexplained internal shorthand recurs without a learner-facing glossary anywhere:** "harness," "deterministic gate," "conceptual tier," and "Skill" (capitalized, ambiguous whether it means a literal Claude Skill file or just "a skill") all appear only in the design doc. None of that is wrong for an internal doc, but nothing yet translates it into "here's what happens when you submit an exercise" for me.

**Bottom line:** the plan itself (subject-beginner scoping, deterministic-then-conceptual gate, sequencing logic) reads sound and respectful of my actual starting point. My complaint is narrower: the one thing I'd currently see has a jargon problem, and the thing that would answer my real questions doesn't exist yet.
